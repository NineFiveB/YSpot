## Entry work (ruled at M0 sign-off; runs before feature work)

| Issue | What | State |
|---|---|---|
| [#7](https://github.com/NineFiveB/YSpot/issues/7) | Fuzzy tier returns wrong pages when `FUZZY_CAP` binds (36/60 real skeleton queries diverge) | **Active.** Measured dead ends: pair-BSI (~1%), segment filters (insufficient at affordable memory), exact-by-construction (over budget), and the whole scalar-scorer avenue — byte-level and ASCII-tight-loop variants are exact but the per-query oracle over both is **1.39×** where ~5× is needed. Remaining, in order: drain-floor/positional pruning (unmeasured), SIMD batch verification (only if pruning fails; still doesn't cover >100k-survivor queries alone), or a design ruling on an explicitly-bounded approximation. |
| [#9](https://github.com/NineFiveB/YSpot/issues/9) | Overlapped pipe I/O, both sides (service inline-search thread + shell 1–2 ms poll loop are interim) | Not started |
| [#11](https://github.com/NineFiveB/YSpot/issues/11) | 1-char query fast path (p95 25–34 ms at 1.09M — the first keystroke of every search) | Not started |
| [#10](https://github.com/NineFiveB/YSpot/issues/10) | Memory model: real mean name length is ~34.6 B, not 23 B; re-derive the §3.4 byte budget | Not started (bookkeeping; informs any #7 fix that spends B/entry) |

\#7 is entry work by explicit ruling. #9 and #11 are latency debt on the
critical path of every keystroke; do them before the launcher becomes a daily
driver. #10 is an afternoon of re-derivation and gates any fix that wants to
spend memory.

## Feature scope (SPEC §10 M1), in build order

Phase 1 — minimum dogfoodable (the switch-over set):

1. **App launching** (§7.1): Win32 via Start Menu folders + UWP via
   `AppsFolder`; the launcher's most-used function.
2. **File search actions** (§7.3): open, reveal in Explorer, copy path, copy
   file — the index already answers; the UI grows verbs.
3. **Tray icon + single instance** (§5.5) and **autostart** (§5.4): the
   launcher must survive logon and be recoverable when hidden.
4. **Multi-monitor placement** (§5.3).

Phase 2 — daily-driver parity:

5. **Calculator** (§7.7) — inline evaluation, copy on Enter.
6. **ms-settings catalog + Control Panel tasks** (§7.2).
7. **Settings window** (§5.9; the non-wizard half) — hotkey rebind, scope
   toggles, autostart opt-out.
8. **Clipboard history** (§7.4) and **window management** (§7.5) — native,
   shell-side; the §7.8 placement table is normative on what must NOT be an
   extension.

Phase 3 — exit-criteria hardening:

9. **Onboarding wizard** (§5.9): hotkey confirm → service consent (elevated
   MSI, skip path) → scope selection → autostart → diagnostics consent.
10. **Shell-side OleDB fallback** (§3.1: `107 SCOPE_UNSUPPORTED` routing) and
    **portable mode** (§9.5) — same code path; portable mode is an exit
    criterion.
11. **Crash reporting, opt-in** (§8.5).
12. **Accessibility pass** (§5.12): UIA tree, Narrator + NVDA end-to-end —
    exit criterion, not polish; verify per phase rather than at the end.
13. **CI keeps M0 budgets green** (shared-runner `bench` as the advisory
    tripwire; the reference-hardware harness stays deferred with Machine B
    per the §10 amendment).

## Exit criteria (SPEC §10 M1 — measured, not eyeballed)

- [ ] Author dogfoods **exclusively** for 2 weeks; no daily crash.
- [ ] All M0 budgets still green under the CI benchmark.
- [ ] Portable mode functional (§9.5).
- [ ] Operable end-to-end with Narrator and NVDA (§5.12).

column of `docs/M0.md` stays open as a post-M0 obligation; issue #7's
tripwire is the bench's fuzzy-survivor table (`capped` column).
